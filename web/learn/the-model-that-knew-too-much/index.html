Normal case · data forensics in Python

The Model That Knew Too Much

Spot target leakage before you train a model.

A salary model scored perfectly on its first try. The CFO doesn't trust perfect.

Play this case →

The story

Halvorsen Freight hired a consultant to build a model that predicts what each of its 800 employees should earn. On the first run it was flawless. Every prediction landed on the right side of the line.

The consultant sent a celebratory email. CFO Ingrid Halvorsen did not reply to it. She has sat through enough board meetings to know that a perfect model usually means someone let it see the answers.

She has handed you the training table. Somewhere in these columns is a source that knows more than it should. Find it before the model goes live.

What you'll practise

  • correlation matrices
  • groupby against the target
  • asking what a model is allowed to know

The fault is a relationship: a feature against the target, against time, or against another source. You write real pandas, NumPy and scikit-learn code in a notebook that runs in your browser. Nothing to install.

The data

HR wants to predict 'salary' from the other columns for a compensation model. One of the feature columns is suspicious -- it wouldn't actually be available before you know the answer. Find it. 800 rows, loaded as df.

ColumnWhat it holds
employee_idint, unique id
years_experienceint, 0-29
educationcategorical
departmentcategorical
performance_scoreint, 1-5
bonus_eligible_flagint, 0 or 1, HR-set flag
salaryfloat, USD -- the prediction target
